# Dependency Policy

## Principles

ScolaOS keeps the mandatory runtime surface deliberately small. A dependency is accepted only when it materially improves correctness, security, maintainability, interoperability, or delivery speed compared with owning the capability directly.

The repository currently follows a **direct-to-`main` policy**. Dependency tooling must not create automated branches or pull requests.

## Admission checklist

Before adding or upgrading a production dependency, review:

1. maintenance activity and ownership;
2. security/advisory history;
3. license compatibility with AGPL-3.0-only distribution;
4. transitive dependency cost;
5. runtime/bundle impact;
6. ability to self-host without a proprietary service;
7. replacement/exit path;
8. whether the capability belongs behind an adapter;
9. compatibility with the pinned Node/TypeScript/toolchain versions.

## Versioning

- Root toolchain dependencies are exact-pinned.
- Application dependencies should normally use exact versions until the first stable release process is proven.
- `pnpm-lock.yaml` is required in source control once generated by the approved toolchain.
- CI must switch to frozen-lockfile installation immediately after the lockfile is committed.
- Major updates are reviewed individually.
- Minor/patch updates are reviewed manually and committed directly to `main` in a coherent maintenance batch after validation.
- Automated dependency PR/branch creation is disabled.

## Current TypeScript pin

TypeScript is intentionally pinned to 6.0.x while the selected typescript-eslint line officially supports TypeScript `>=4.8.4 <6.1.0`. Upgrade to TypeScript 7 only after the linter/parser stack declares support and the full quality gate passes without suppressing unsupported-version diagnostics.

## Automated checks

- Existing GitHub Actions security workflow runs `pnpm audit --audit-level=high` on `main` pushes and weekly.
- Existing CI runs on direct pushes to `main`.
- GitHub public-repository secret scanning is relied on for repository secret detection; push protection should remain enabled in repository security settings.
- Dependency version discovery is manual while the direct-to-main policy is active; no bot may open dependency PRs.

Security alerts are triaged by exploitability, affected path, data exposure, and whether the dependency is present in a shipped runtime or development-only tooling.
