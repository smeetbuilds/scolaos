# Changelog

All notable changes to the project currently stored in the `smeetbuilds/scolaos` repository will be documented in this file.

The project is currently pre-alpha and follows milestone-driven development.

## [Unreleased]

### Added

- Established M0 Fastify, platform-contract, support-matrix and design-definition foundations plus prepared PostgreSQL/Drizzle acceptance work.
- Added M1 installer, authorization, identity, audit, health and institution-domain foundations.
- Added installer requirements diagnostics, durable progress/recovery, safe pre-DB config correction and verifier-required finalization.
- Added first-school bootstrap domain normalization for institution, default branch, initial active academic session and administrator setup.
- Added retry-safe transactional bootstrap port covering seed + institution + branch + session + administrator user + membership + role assignment + completion receipt.
- Added deterministic installation seed plan validation against the permission catalog/default-role templates, including SHA-256 content fingerprinting.
- Added permanent bootstrap/seed regression suites and `docs/pocs/installer-bootstrap.md`.
- Added contributor/open-source readiness documentation covering development, architecture, API, jobs and coordinated security disclosure.

### Changed

- M0-004 server support matrix remains DONE: Linux x86_64, Node 24.x LTS and PostgreSQL 16–18/current-minor policy.
- M1-014/M1-015/M1-016 are now backend/domain-contract complete but remain IN PROGRESS until responsive installer UI/runtime persistence integration exists.
- M1-032/M1-033 now have a deterministic validated seed source and integrity descriptor but remain IN PROGRESS until PostgreSQL application/journal evidence exists.
- M1-034 now has an explicit retry/idempotency transaction contract but remains IN PROGRESS until the real PostgreSQL adapter proves atomic rollback/constraints.
- M1-073 term/semester model remains DONE; M1-070/071/072/074/075 remain domain-founded/persistence-pending.
- GitHub Actions remain manual-only at the owner's request.

### Security / Integrity

- Bootstrap entity IDs are generated by trusted runtime code rather than accepted from client setup data.
- Raw initial-administrator password and confirmation never enter persistence records or bootstrap receipts.
- A password-hasher implementation returning the raw administrator password is rejected.
- Duplicate generated bootstrap identifiers are rejected before persistence.
- Completed bootstrap replay uses a durable receipt and is rechecked inside the transaction for concurrency safety.
- Initial Super Administrator seeding fails validation unless every current permission is explicitly granted.
- Seed versions are coupled to a deterministic content fingerprint so catalog/template drift can be detected independently of version labels.

- Direct-to-`main` workflow remains unchanged.
- No dependency, lockfile, branch, PR or Actions workflow change is introduced by the installer-bootstrap tranche.
- M0-031 remains the main architecture blocker; no PostgreSQL/Drizzle success is claimed from repository ports or transactional fakes.
